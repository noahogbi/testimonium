# testimonium 0.6.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop `toText` attesting text that is not on the page, by matching per region and by parsing attributes instead of pattern-matching tag strings.

**Architecture:** Extraction gains an internal region view — the body plus each distinct description value. `toText` becomes the join of those regions and its output is unchanged. Claim matching, harvest's span proposal, and excerpt location all move from the flat string to the regions. Separately, `IS_DESCRIPTION` and `CONTENT_ATTR` are replaced by an attribute parser.

**Tech Stack:** TypeScript, vitest, Node >= 20, zero runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-09-20-testimonium-0-6-0-design.md` — four review rounds, and §8 records a route that was cut. Read it before Task 1.

## Global Constraints

- **Zero runtime dependencies.** `package.json` has no `dependencies` key; it stays that way.
- **`toText`'s output must be byte-identical after Task 2** (the region split) and changes ONLY through Task 1 (attribute parsing). Task 2 proves this over every fixture.
- **Never write a NUL byte**, and sweep for unintended non-ASCII codepoints — a NUL check alone misses a zero-width joiner.
- **Files are CRLF.** The Write tool emits bare LF here; convert and byte-verify by byte count, not `grep -c $'\r'`, which undercounts in Git Bash.
- `tsc --noEmit` type-checks `test/` as well as `src/`; vitest does not type-check. Run both.
- **Do NOT run `fixtures/challenge-battery.mjs`** — it rewrites tracked fixtures. `calibrate.mjs` and `sweep-floor.mjs` are read-only and safe.
- Baseline is **585 tests / 46 files**, `tsc` exit 0.

- [ ] **Step 3: Write the parser**

In `src/text/extract.ts`, DELETE `IS_DESCRIPTION` and `CONTENT_ATTR` and add:

```ts
/** A tag's attributes, by lowercased name, FIRST occurrence winning. Replaces
 *  two regexes that matched substrings of the whole tag: `\bcontent\s*=` fired
 *  inside `data-content`, and both fired inside another attribute's VALUE, so
 *  the wrong text was harvested and the real description was lost. Values are
 *  matched case-insensitively by the caller, because `name="Description"` is
 *  ordinary legacy CMS output.
 *
 *  Unquoted values are deliberately NOT collected: 0.5.0 never harvested them,
 *  and accepting them here would newly harvest `name=description` on pages this
 *  release is not otherwise changing. */
function parseAttrs(tag: string): Map<string, string> {
  const attrs = new Map<string, string>();
  // Strip the angle brackets. The tag name needs no skipping: it carries no `=`.
  const body = tag.slice(1, -1);
  const re = /([a-zA-Z_:][-a-zA-Z0-9_:.]*)\s*=\s*(["'])([\s\S]*?)\2/g;
  let m: RegExpExecArray | null;
  while ((m = re.exec(body)) !== null) {
    // `as string`: the repo runs noUncheckedIndexedAccess, so a matched group
    // types as string | undefined even though the regex guarantees it here.
    const name = (m[1] as string).toLowerCase();
    if (!attrs.has(name)) attrs.set(name, m[3] as string);
  }
  return attrs;
}

const DESCRIPTION_VALUES = new Set(["description", "og:description", "twitter:description"]);
```

Then rewrite `descriptionText`'s filter:

```ts
    const attrs = parseAttrs(tag);
    const key = (attrs.get("name") ?? attrs.get("property") ?? "").trim().toLowerCase();
    if (!DESCRIPTION_VALUES.has(key)) continue;
    const value = attrs.get("content")?.trim();
    if (value) seen.add(value);
```

**The regex consumes each quoted value, so a `content=` appearing inside an earlier
attribute's value is never seen as an attribute** — that is the whole point, and it is why
the parser must scan left to right rather than search.

**Two micro-divergences from 0.5.0 that this shape introduces.** Neither is in the spec's
grammar table; both are accepted, and each gets a test so the next reader knows it was
decided rather than overlooked:

- `.trim()` on the key newly harvests `name=" description "`. 0.5.0 did not. This is
  more permissive than 0.5.0 and than a browser: HTML5 matches metadata names
  exactly, so a padded value selects nothing for a browser. A deliberate
  widening in the text-ADDING direction, which must be disclosed.
- `attrs.get("name") ?? attrs.get("property")` drops a tag carrying BOTH `name="author"` and
  `property="og:description"`, which 0.5.0 harvested. Prefer whichever attribute carries a
  description value rather than preferring `name` blindly:

```ts
    const candidates = [attrs.get("name"), attrs.get("property")];
    const key = candidates.map((v) => (v ?? "").trim().toLowerCase()).find((v) => DESCRIPTION_VALUES.has(v));
    if (!key) continue;
```

```ts
/** The body plus each distinct description value, as separate strings. The
 *  regions exist because a claim must not be matchable across the join between
 *  them: `toText`'s flat output concatenates them, and a phrase spanning that
 *  boundary appears nowhere on the page. Index 0 is always the body.
 *
 *  Each region runs the entity/whitespace chain independently and the join is a
 *  single space, which reproduces `toText` byte for byte because the chain
 *  trims each part - proven over every fixture in extract-regions.test.ts. */
export function toTextRegions(html: string): string[] {
  const stripped = html
    .replace(/<script[\s\S]*?<\/script>/gi, " ")
    .replace(/<style[\s\S]*?<\/style>/gi, " ");
  const forHarvest = stripped
    .replace(/<script\b[\s\S]*?(?:<\/script>|$)/gi, " ")
    .replace(/<style\b[\s\S]*?(?:<\/style>|$)/gi, " ")
    .replace(/<!--[\s\S]*?(?:-->|$)/g, " ")
    .replace(/<template\b[\s\S]*?(?:<\/template>|$)/gi, " ");
  const body = finish(stripped.replace(/<[^>]*>/g, " "));
  const out = body ? [body] : [];
  for (const v of descriptionValues(forHarvest)) {
    const f = finish(v);
    if (f) out.push(f);
  }
  return out;
}

export function toText(html: string): string {
  return toTextRegions(html).join(" ");
}
```
