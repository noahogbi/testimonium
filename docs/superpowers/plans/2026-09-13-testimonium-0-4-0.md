# testimonium 0.4.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship TypeScript declarations for the first time, and close four findings carried from earlier releases.

**Architecture:** Nothing here changes a verdict or a runtime value. Two source annotations widen literal types before they can be committed to; nine type-only exports make already-crossing shapes nameable; declaration emit is switched on and verified across three module-resolution modes; two pure functions are lifted out of the CLI so their drift is testable. The rest is documentation.

**Tech Stack:** TypeScript, ESM, Node >= 20, vitest, zero runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-09-13-testimonium-0-4-0-design.md`. Read it before Task 1 — its §8 records what review changed.

**Baseline:** 550 tests passing, `tsc --noEmit` clean. Verify that before Task 1; if you see a different number, stop and report.

## Global Constraints

- Node >= 20. Zero runtime dependencies — `package.json`'s `dependencies` must stay `{}`.
- `exactOptionalPropertyTypes` is on.
- `npm pack` must ship only `dist/` plus standard metadata. After Task 3 it also contains `.d.ts` files, which is the point; nothing else changes.
- **Do NOT run `fixtures/challenge-battery.mjs`** — it rewrites tracked fixtures.
- Never write a literal NUL byte into a file. Byte-check with `node` after writing (python may be absent from PATH); four NUL incidents have already occurred in this project.
- `VERSION` in `src/version.ts` and `version` in `package.json` are held equal by `test/exports.test.ts`.
- **The runtime export allowlist in `test/exports.test.ts` must not change.** Every addition here is type-only and cannot appear in an `Object.keys` pin. If that test needs editing, stop and report.
- **No verdict may move. No threshold VALUE changes.** `THRESHOLDS` stays frozen at runtime.
- `tsc --noEmit` DOES type-check `test/` — `tsconfig.json` includes it. **Vitest does not type-check**; it transpiles through esbuild. Any test whose subject is a type is therefore verified by `npx tsc --noEmit`, never by `npm test`.
- Publishing is NOT part of this plan. Do not tag, publish, or push.

- [ ] **Step 1: Write the failing type assertions**

**The probe must compare against a LITERAL, not against a `string`-typed variable.** A literal type always overlaps its base type, so `VERSION === someString` compiles whether `VERSION` is `"0.3.0"` or `string` — it can never fail. Measured: that form exits 0 against a literal-typed mock, while `VERSION === "0.99.0"` raises TS2367. An earlier draft of this plan used the form that cannot fail.

In `test/exports.test.ts`:

```ts
it("VERSION is typed string, not a literal - or every release is type-breaking", async () => {
  const { VERSION } = await import("../src/index.js");
  // Comparing to a LITERAL is the probe. Against `VERSION: "0.3.0"` this line
  // is TS2367 and `tsc --noEmit` fails; against `VERSION: string` it compiles.
  expect(VERSION === "0.99.0").toBe(false);
  expect(typeof VERSION).toBe("string");
});
```

Create `test/classify/thresholds-types.test.ts`:

```ts
import { describe, it, expect } from "vitest";

describe("THRESHOLDS types", () => {
  it("values are typed number, not literals - recalibration must not be breaking", async () => {
    const { THRESHOLDS } = await import("../../src/index.js");

    expect(THRESHOLDS.maxChallengeChars === 999).toBe(false);
```

- [ ] **Step 1: Write the failing pin**

Reads `src/index.ts` as TEXT — **not** `dist/`, which `npm test` never builds and which would pass vacuously on a clean checkout.

```ts
import { describe, it, expect } from "vitest";
import { readFileSync } from "node:fs";

/** Both export syntaxes. `export { x, type Y }` and `export type { A, B }` are
 *  both in use, and an earlier sweep matching only the first reported 8 of 14 -
 *  an instrument error that looked exactly like a spec error. */
function exportedTypeNames(src: string): string[] {
  const inline = [...src.matchAll(/\btype\s+([A-Za-z]\w*)/g)].map((m) => m[1]!);
  const blocks = [...src.matchAll(/export\s+type\s*\{([^}]*)\}/g)]
    .flatMap((m) => m[1]!.split(",").map((s) => s.trim()))
    .filter(Boolean);
  return [...new Set([...inline, ...blocks])].sort();
}

const EXPECTED = [
  "BuiltinRung", "CheckOptions", "CitationResult", "ClaimEntry", "ClaimProblem",
  "ClaimsFile", "Document", "Evidence", "FailOn", "Fetcher", "FetcherOptions",
  "FiredRule", "Footnote", "HostRule", "Joined", "RawResponse",
  "ReachabilityOptions", "ReachabilityResult", "Rule", "RuleSet", "RunTally",
  "RungId", "Verdict",
].sort();

describe("public type surface", () => {
  it("exports exactly the pinned 23 types - an addition is as much a change as a removal", () => {
    const src = readFileSync(new URL("../src/index.ts", import.meta.url), "utf8");
    expect(exportedTypeNames(src)).toEqual(EXPECTED);
  });
});
```

`EXPECTED` must hold 23 entries — count them before running. This function was executed against the real `src/index.ts` during review and returns exactly the current 14, so the red step is genuine.

### Task 4: Make the CLI tally and flag-wiring importable, and test their drift

**Files:**
- Modify: `src/bin.ts`
- Modify: `test/bin.test.ts`

**Interfaces:**
- Produces: two pure exported functions beside the existing `classifyRecheckRun` / `renderOutcome` / `jsonOutcome` trio. **Neither is added to `src/index.ts`.**

**Read `src/bin.ts:730-746` before writing anything.** The real tally is:

```
unsupported                      <- counted from results
unclaimed:  joined.unclaimed.length
unreachable                      <- counted from results
orphaned:   joined.orphanedClaims.length
infrastructure: false
```

**`unclaimed` and `orphaned` do NOT come from verdict rows.** Unclaimed footnotes never reach `check()`, so no result ever carries a `"unclaimed"` verdict in `main()`'s flow. An earlier draft of this plan sketched `tallyFor(results, orphaned)` deriving unclaimed from a verdict row — a flow that does not exist. **Implementing that sketch would make the CLI's unclaimed count permanently 0**, collapsing the gate the design calls its named top risk, with a green suite.

So the extracted signature takes both inputs:

```ts
export function tallyFor(results: readonly CitationResult[], joined: Joined): RunTally
export function failOnFor(flags: ReadonlySet<string>): FailOn
```

`failOnFor` exists because the ledger's named drift case is "a flag that stops being wired to `classifyRun`" — that is the argv-to-`FailOn` mapping, which no test can reach while it is inline in `main()` (which builds its own fetcher and cannot be driven with a stub).

**Note, and do not change it in this task:** the CLI wires only `unreachable` and `unclaimed`. It never sets `orphanedClaims`, so an orphaned claim cannot fail a CLI run today. Record that in your report as an observation for the owner; changing it is a behaviour change and out of scope.

- [ ] **Step 1: Leave the library-parity test alone**

Read its docstring first. It says importing only `src/index.js` **is the thing under test**. Rewiring it to import `bin.ts`'s internals guts that premise. **This step is a deliberate non-action** — confirm it, do not edit it.

- [ ] **Step 2: Write the failing tests**

**Each flag must be tested with a tally where ONLY its own field is non-zero.** Measured against the real `classifyRun`: with `{unsupported:0, unclaimed:1, unreachable:1, orphaned:1}`, the results for `{unreachable:true}` and `{unreachable:false}` are **both 1** — the unclaimed clause defaults to failing and dominates every row, so the flag under test never determines the outcome. An earlier draft used exactly that masked table.

```ts
const ZERO = { unsupported: 0, unclaimed: 0, unreachable: 0, orphaned: 0, infrastructure: false };

it.each([
  ["unreachable",    { ...ZERO, unreachable: 1 }, { unreachable: true },     { unreachable: false }],
  ["unclaimed",      { ...ZERO, unclaimed: 1 },   {},                        { unclaimed: false }],
  ["orphanedClaims", { ...ZERO, orphaned: 1 },    { orphanedClaims: true },  {}],
])("%s reaches the exit code, and only when its flag says so", (_n, tally, on, off) => {
  expect(classifyRun(tally, on)).toBe(1);
  expect(classifyRun(tally, off)).toBe(0);
});

it("sources unclaimed and orphaned from joined, not from verdict rows", () => {
  const results = [{ url: "a", verdict: "supported" }, { url: "b", verdict: "unreachable" }] as CitationResult[];
  const joined = { unclaimed: ["x", "y"], orphanedClaims: ["z"] } as unknown as Joined;
  expect(tallyFor(results, joined)).toEqual({
    unsupported: 0, unclaimed: 2, unreachable: 1, orphaned: 1, infrastructure: false,
  });
});

it("maps each argv flag to its FailOn field", () => {
  expect(failOnFor(new Set())).toEqual({ unreachable: false, unclaimed: true });
  expect(failOnFor(new Set(["--fail-on-unreachable"]))).toMatchObject({ unreachable: true });
  expect(failOnFor(new Set(["--allow-unclaimed"]))).toMatchObject({ unclaimed: false });
});
```

Match the real `Joined` shape from its defining module rather than the cast above, and derive every expected value from `bin.ts`'s CURRENT behaviour — this task must not change what the CLI does.

- [ ] **Step 3: Run and watch them fail**

Expected: FAIL — the functions do not exist.

- [ ] **Step 4: Extract both functions**

Move the tally computation and the `FailOn` construction out of `main()` into pure exported functions beside the recheck trio. `main()` calls both. **Behaviour must not change**; any difference is a defect.

- [ ] **Step 5: Run and watch them pass**

Run: `npx vitest run test/bin.test.ts` then `npm test`

- [ ] **Step 6: Prove drift is now caught — per field and per flag**

The task's whole point, and the step that must not be skimmed. For EACH tally field and EACH wired flag: mutate the extracted function (miscount one field; unwire one flag), confirm a test goes red, restore. Record each mutation and its result.

**If any mutation leaves the suite green, the coverage is insufficient and the tests must be strengthened before proceeding.** Reproducing that would mean the task failed while appearing to succeed — which is precisely the finding it exists to close.

## Ordering

| edge | why |
| --- | --- |
| **1 before 3** | the first published declarations are what consumers pin against; emitting before the widening ships `VERSION` as a literal and every threshold as its current value, both then breaking to change |
| **2 before 3** | emitting before the nine exports ships an incomplete surface |
| 1, 2 before 4 | no hard dependency, but 4 touches `bin.ts` and a red suite from either would make its verification unreadable |
| 1-5 before 6 | the changelog describes them |

Tasks 4 and 5 are independent of each other and of 3. **Run everything sequentially regardless** — the suite is the shared surface.
