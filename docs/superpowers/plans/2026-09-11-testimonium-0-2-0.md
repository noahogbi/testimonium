# testimonium 0.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the eighteen capabilities a real integration found missing, so this package can replace the tool it was extracted from without losing functionality.

**Architecture:** Six behaviour changes and four API-surface additions. The headline change - escalating the ladder before making an accusation - is triggered in `check()`, which already owns the verdict, while `nextAction` gains a flag and stays claim-blind. Three changes reverse doctrine the binding spec states positively, so each carries an amendment to that spec at every site the sentence appears.

**Tech Stack:** TypeScript (strict), Node >= 20, vitest, zero runtime dependencies, ESM.

**Spec:** `docs/superpowers/specs/2026-09-11-testimonium-0-2-0-design.md`, which amends `docs/superpowers/specs/2026-09-06-testimonium-design.md`. **Read both.** The 2026-09-06 spec is the binding authority for everything 0.2.0 does not name; where they disagree, the amendment table in 0.2.0 section 2 is the list of places 0.2.0 wins.

## Global Constraints

- **Node >= 20. Zero runtime dependencies.** `package.json` `dependencies` must stay `{}` - `test/exports.test.ts` pins this.
- **Pure ASCII in every file you write.** Three standing exceptions you must not touch or widen: `src/text/excerpt.ts` (57 non-ASCII bytes), `test/text/excerpt.test.ts` (45), `test/text/extract.test.ts` (3). Zero NUL bytes anywhere.
- **`npm test` green and `npx tsc --noEmit` clean at the end of every task.** State the test total in your report and reconcile it by counting the `it()` blocks you added or removed - never by matching a target.
- **A check must be shown able to fail before its pass is believed.** Prove every mutation applied before trusting what a test says about it. Fourteen verification instruments have silently failed on this project, including a grep-for-absence satisfied by the comment documenting the absence, a check run against a stale `dist/`, and a positive control that could not fire because the word it searched for was not in the file.
- **No verdict may move except as the spec predicts.** Escalation moves `unsupported` to `supported` and nothing else. If you observe any other movement, stop and report it.
- **`test/exports.test.ts` holds an allowlist of the exact runtime export names.** Any change to `src/index.ts` updates it in the SAME commit, never after.
- **This package is published.** 0.2.0 is a real release: the CHANGELOG is a record, not a formality.
- Commit with `git -c core.safecrlf=false commit -m "..."`, conventional prefix with scope.
- Environment: Windows, Git Bash. Every Bash call starts in a fresh cwd - begin with `cd C:/Users/noaho/testimonium &&`. `python` not `python3`. `grep -P` fails in this locale. ### Task 2: Narrow the `/consent/` path veto

**Files:**

**Interfaces:** unchanged.

The rule is `{ pattern: /\/consent(\/|$|\?)/, ... note: "Consent-wall redirect, e.g. consent.youtube.com." }`. Its own note says the target is a consent *host*; the pattern matches any path segment, so it vetoes a data-protection regulator's guidance page at `/en/themes/consent`. `matchesChallengePath` tests the whole `finalUrl`, so a host-anchored pattern still catches the redirect it was written for.

**The shipped rule is the inverse of its own note.** Measured: `/\/consent(\/|$|\?)/`

`https://consent.google.com/ml?continue=x` - the `.` after `consent` breaks the
`(\/|$|\?)` tail - and **true** for both regulator pages. It has never matched
the redirect it was written for, and only ever vetoed path-segment forms. So
this task FIXES and narrows in one move: the veto starts firing on the redirect,
and stops firing on documents about consent.

**This task must not let a real consent wall through.** Both directions are required.

### Task 4: Content-type PDF re-route

**Files:**
- Modify: `src/fetch/read-source.ts` (after `computeSignals`). No change to `src/fetch/pdf.ts` - `isPdf` already accepts the second argument.
- Test: `test/fetch/read-source.test.ts`

**Interfaces:**
- Consumes: `isPdf(url: string, contentType?: string): boolean` - `src/fetch/pdf.ts:24-27` already accepts the second argument and nothing calls it with one.
- Produces: nothing new.

**Every stub `RawResponse` in this plan omits `bytes`, which is REQUIRED** (`src/fetch/types.ts:34`), and the project runs `strict` with `exactOptionalPropertyTypes`. Copy the stub shape from `test/fetch/read-source.test.ts:12` or `test/check.test.ts:20` rather than the literals below, which are illustrative of the call and not complete.

A PDF served from a URL with no `.pdf` is picked as an HTML rung, N5 vetoes the bytes as not-text, and the document reads `unreachable`. **The constraint:** the pick-before-fetch invariant must hold - do NOT fall through to curl on a failed PDF fetch. What is permitted is a `pdftotext` attempt when an HTML rung returns `application/pdf`, which cannot libel HTML as a PDF because the host said so.

- [ ] **Step 1: Write the failing test**

```ts
it("re-routes to the PDF rung when an HTML rung returns application/pdf", async () => {
  const pdfBytes = readFileSync("fixtures/documents/sample.pdf");
  const fetcher: Fetcher = {
    rungs: ["node", "curl", "pdftotext"],
    async fetch(_url, rung) {
      if (rung === "pdftotext") return { rawBody: "The quick brown fox jumps over the lazy dog.", headers: {}, finalUrl: _url, status: 200 };
      return { rawBody: pdfBytes.toString("binary"), headers: { "content-type": "application/pdf" }, finalUrl: _url, status: 200 };
    },
  };
  const out = await readSource("https://example.com/doc", ["quick brown fox jumps"], { fetcher });
  expect(out.attempted).toContain("pdftotext");
});
```

`fixtures/documents/sample.pdf` does not exist - build the body in the test instead. Use a `"\u0000"` ESCAPE in the source, never a literal NUL byte: the global constraints forbid NUL bytes in files you write, and this repository has a recorded incident of an escape round-tripping into the raw character. Byte-check the test file after writing it. The point is a body that is not text arriving with a PDF content-type.

- [ ] **Step 2: Run it and watch it fail**

Run: `npx vitest run test/fetch/read-source.test.ts`
Expected: FAIL - `attempted` is `["node","curl"]`, no `pdftotext`.

- [ ] **Step 3: Re-route inside the loop**

After `reads.push(...)` and before `history.push(...)`, add:

```ts
    // A PDF served from a URL with no .pdf extension. The rung was picked from
    // URL shape before any fetch, so N5 vetoes these bytes as not-text and the
    // document reads `unreachable`. The HOST has now told us what it is, so
    // one pdftotext attempt is licensed - the direction that cannot libel HTML
    // as a PDF. The pick-before-fetch invariant still forbids falling through
    // to curl on a FAILED PDF fetch; this is the other direction.
    // Header keys are case-insensitive by contract (src/fetch/types.ts:23-31):
    // a fetcher "may pass a server's own casing straight through". Reading
    // headers["content-type"] raw would silently miss `Content-Type` and leave
    // the document `unreachable` - this task's own defect, recurring by casing.
    const ctype = Object.entries(response.headers).find(
      ([k]) => k.toLowerCase() === "content-type",
    )?.[1];
    if (
      !pdfUrl &&
      isPdf(url, ctype) &&
      opts.fetcher.rungs.includes("pdftotext") &&
      !attempted.includes("pdftotext")
    ) {
      const pdfRead = await opts.fetcher.fetch(url, "pdftotext");
      attempted.push("pdftotext");
      const pdfComputed = computeSignals({
        rawBody: pdfRead.rawBody,
        headers: pdfRead.headers,
        finalUrl: pdfRead.finalUrl || url,
        status: pdfRead.status,
        claims,
        sourceLabel: opts.sourceLabel ?? "",
        ...(opts.rules ? { rules: opts.rules } : {}),
      });
      reads.push({ rung: "pdftotext", computed: pdfComputed });
      history.push({ rung: "pdftotext", readable: isReadable(pdfComputed.signals) });
      break;
    }
```

Import `isPdf` with its second argument in mind; it is already imported in this file.

Run: `npx vitest run` then `npm test`
Expected: pass. **Watch for corpus movement** - a fixture whose headers carry a PDF content-type would now take a new path. If any verdict moves, report it before continuing.

- [ ] **Step 5: Prove the re-route is what passed the test**

Change `isPdf(url, response.headers["content-type"])` to `isPdf(url)`, re-run, confirm RED. Restore.

 * accuse and a rung is untried (spec 0.2.0 section 4). The prior reads are
 * carried forward, so the rung already fetched is not fetched again.

 * `readable` is `isReadable(computed.signals)`, which is exactly what the
 * original loop pushed.
 */
export async function continueReading(
  url: string,
  claims: readonly string[],
  opts: ReadSourceOptions,
  prior: SourceReads,
): Promise<SourceReads> {
  const history: Attempt[] = prior.reads.map((r) => ({
    rung: r.rung,
    readable: isReadable(r.computed.signals),

  const attempted: RungId[] = [...prior.attempted];
  const reads: Read[] = [...prior.reads];
  await climb(url, claims, opts, prior.pdfUrl, history, attempted, reads, true);
  return { reads, attempted, pdfUrl: prior.pdfUrl };
}
